# Priority framework (defaults)

The user can override any default. State an override in one line.

## Dimensions

| | High | Medium | Low |
|---|---|---|---|
| **Space** | Central and growing; others depend on it; it leads to bigger scope | A useful niche | Peripheral or shrinking |
| **Value now** | Someone feels the problem today | Useful, but nobody waits on it | Nice to have |
| **Compounding** | Leaves an owned, reusable asset: a platform, an interface, a decision record, a relationship, a skill | Reusable, but not owned or seen | Gone once done (terminal) |
| **Cost of delay** | A window closes, a risk grows, or someone else takes it | Slower, but still possible later | Same value next quarter |
| **Effort** | Weeks, or blocked | Days | Hours |
| **Confidence** | Evidence: decisions, allocations, data, written commitments | Mixed | Hints, guesses or a single remark |

## Default order

1. Occupies the most valuable open space: central, growing, and it opens bigger work.
2. An early claim on that space over a late, perfect artifact.
3. Enabling work.
4. Work that compounds only if seen, done with its visibility step.
5. Terminal work. Do it only when forced, and keep it small.

## Compounding ladder

`terminal task → reusable piece → owned component → owned platform or
decision area`. Prefer the option that climbs highest that you can credibly take. Ownership comes from
claiming, not from finishing the previous stage.
